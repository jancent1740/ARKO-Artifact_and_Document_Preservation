1. GLOBAL / BASE TYPOGRAPHY SYSTEM
================================================================================

APPLIED VIA: /src/styles/globals.css  (imported in /src/styles/index.css)
FONT IMPORT:  /src/styles/fonts.css   (first line of index.css)

  Primary Font Family (Global):
    font-family: 'Roboto', sans-serif
    Applied to:   All elements via `*` selector and `body` selector
    Import URL:   https://fonts.googleapis.com/css2?family=Roboto:wght@400;500;700&display=swap
    Weights loaded from Google Fonts: 400 (Regular), 500 (Medium), 700 (Bold)

  Base Font Size (html root):
    font-size: 16px  (via CSS variable --font-size: 16px)

  Font Smoothing (body):
    -webkit-font-smoothing: antialiased
    -moz-osx-font-smoothing: grayscale

  IMPORTANT NOTE:
    The imported Figma components (HomepageLandingPortalPart2–Part6) were
    translated directly from Figma and internally reference:
      font-['Inter:Regular',sans-serif]
      font-['Inter:Semi_Bold',sans-serif]
      font-['Inter:Bold',sans-serif]
      font-['Inter:Light',sans-serif]
    These are Figma-specific font references. In the browser, 'Inter' must be
    loaded separately for these to render correctly, otherwise they fall back to
    the global 'Roboto' family. The sans-serif fallback is always present.
    The global Roboto declaration in globals.css acts as the fallback for all
    components that do not explicitly specify Inter.

9. NOTES & OBSERVATIONS
================================================================================

  1. DUAL FONT SYSTEM:
     The main portal operates with two overlapping font systems:
     - Global CSS (globals.css): 'Roboto', sans-serif — applied to all elements
     - Figma-exported components: 'Inter:*', sans-serif — embedded in className
     In practice, the Inter references will only render correctly if Inter is
     loaded separately (not currently imported in fonts.css). The Roboto global
     declaration acts as fallback for all elements. The visual result on-screen
     depends on whether Inter is loaded at runtime.

  2. FONT SIZE PRECISION:
     Font sizes throughout are specified with sub-pixel precision (e.g. 13.234px,
     16.594px, 68.203px). These values are direct Figma exports and reflect exact
     design intent. In a production implementation, these would typically be
     rounded to nearest 0.25px or 0.5px for consistency.

  3. FIGMA FONT CLASS NAMING CONVENTION:
     The Figma-exported components use the pattern:
       font-['Inter:Weight_Name',sans-serif]
     Where Weight_Name maps to:
       Regular     → 400
       Semi_Bold   → 600
       Bold        → 700
       Light       → 300

  4. SECTION HEADING SIZES:
     All major section headings (H2-level) across the portal fall in the
     34–35px range, maintaining visual consistency:
       "Explore Our Museums"           34.594px
       "Featured Artifacts & Documents"34.875px
       "Quick Information Access"      34.453px

  5. HERO TYPOGRAPHY SCALE:
     The hero section uses the largest display type in the entire portal:
       H1 headline: 68–69px (split across two divs in Figma export)
     This is approximately 4.25–4.33rem on a 16px base.

  6. WHITE OPACITY LAYERING (Footer):
     The footer uses a consistent opacity system for visual hierarchy on dark bg:
       White 100% → primary headings and brand name
       White 80%  → secondary body text and contact details
       White 70%  → tertiary supporting labels
       White 60%  → least prominent: copyright, legal links, hours note

  7. ACCENT COLOR USAGE (#AC0000):
     The museum primary accent (Heritage Red #AC0000) is used typographically
     only in the Events & Timeline section for year display labels and category
     badges. All other sections use the Slate/Teal palette.

  8. TEAL ACCENT (#0f766e):
     Teal is used for positive-status badges ("Open daily", "Heritage Collection",
     "Over 2,000 items") and solid category badges on artifact cards. It signals
     availability, categorization, and collection identity throughout the portal.

  9. NO ITALIC TEXT:
     All text throughout the main landing portal is specified as not-italic
     (the Figma export explicitly sets `not-italic` on all text containers).

  10. TEXT ALIGNMENT:
      Section headers and their badges/subtitles are center-aligned.
      Card content, descriptions, navigation, and footer text is left-aligned.
      Stat card numbers and labels are center-aligned within their containers.
      Buttons use center-aligned text internally.
